# Use a Terraform module from Pulumi (Python)

Consumes a **local Terraform module** (`modules/app-segment/`) from a Pulumi
program written in Python. `pulumi package add terraform-module` generates a
typed Python SDK for the module, so from the program the module is just another
resource: typed inputs in, outputs back.

The module stands in for a real "app segment" resource (e.g. Zscaler): it takes
`name`, `domains`, `port` and allocates one ID per segment plus one policy ID
per domain — using only the `random` provider, so it needs no cloud account.

## How this maps to Terraform
- A Pulumi **stack** ≈ a Terraform workspace (one deployment of this config).
- The generated SDK's `appsegment.Module(...)` ≈ a `module "..." {}` block; the
  handoff is `variables.tf` → typed constructor kwargs, `outputs.tf` → resource
  attributes you read in code (`mod.segment_id`, `mod.domain_policy_ids`).

## Variant: pulumi-hcl
[`pulumi-hcl/`](pulumi-hcl/) consumes the same module with the
[pulumi-hcl](https://github.com/pulumi/pulumi-hcl) plugin instead of
`terraform-module`. The module gets a `PulumiPlugin.yaml` (`runtime: hcl`) and
becomes a multi-language component that pulumi-hcl's own HCL interpreter runs;
the Python program is otherwise identical. See its README for a side-by-side.

## Prerequisites
- Pulumi CLI **3.273.0** (tested)
- Python **3.9+** (tested 3.13) — the `random` provider plugin is fetched automatically

## Run it
```bash
# Credential-free local backend + throwaway secrets passphrase (no Pulumi Cloud).
export PULUMI_CONFIG_PASSPHRASE=dev
pulumi login --local

python3 -m venv venv              # Pulumi uses this venv (virtualenv: venv)
pulumi install                    # regenerates sdks/appsegment from Pulumi.yaml, installs it
pulumi stack init dev
pulumi preview                    # 8 resources to create
pulumi up --yes
pulumi stack output               # segment_ids, web_policy_ids, web_listen_port
pulumi destroy --yes
```

Expected `up` output: `segment_ids` (map `web`/`api` → hex IDs), `web_policy_ids`
(2 hex IDs), `web_listen_port: 443`.

## IDE autocomplete
The generated SDK lives in `sdks/appsegment/` (regenerated by `pulumi install`;
git-ignored). Because it's a real typed package installed in `venv`, editors
autocomplete `appsegment.Module(...)` kwargs (`name`, `domains`, `port`) and the
output attributes. Point your interpreter at `./venv` to see it.

## The module was first added with
```bash
pulumi package add terraform-module ./modules/app-segment appsegment
```
This recorded the `packages:` entry in `Pulumi.yaml`; `pulumi install` replays it.
